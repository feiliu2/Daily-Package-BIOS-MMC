端到端执行流程

先完成 BIOS 阶段，再进入 MMC 阶段

正常入口：计划任务或手动执行完整流程。补打 MMC：使用 --bios-archive，直接从第 05 步开始，不重新打包 BIOS，也不清空输出目录。

A

BIOS 打包

保留原始命令、配置文件和工作目录

  1. 01

    到点触发

    Windows 计划任务启动 package_latest_bios.py，默认本机时间每天 15:00，使用注册时固定的 Python 可执行文件。

    OakStream-BIOS-Daily-Package
  2. 02

    发现最新 BIOS

    读取 BIOS Artifactory 索引，按版本号数值比较，不依赖网页顺序、字符串排序或目录修改时间。

    OAKSTRM.0.RPB.0040.D.79/
        ↓
BIOS ID: 0040D79
Archive: 0040.D79.7z
  3. 03

    原位置执行原命令

    工作目录：

    C:\OKS\OakStreamAPIfwi\Ifwi\oak_release\BuildScripts\CommonLib\BIOS_Repackaging
    python restructure_new.py --bios=0040D79 --package_fdr_file=0040.D79.7z --file_path=C:\LocalPath\Bios --config_ini=config_oak_ap.ini
    • 原 INI 只读，不生成临时 INI，不改写工作空间。
    • 原脚本在 C:\ATF 下载和处理 BIOS。
    • 压缩包直接写入 C:\LocalPath\Bios。

    最新一组模式：原 BIOS 脚本会清空输出目录，再写入新包。旧 BIOS、旧 MMC 和其他文件不会保留；同一 BIOS ID 也会重新打包。

  4. 04

    验证 BIOS，再清空缓存

    原命令成功退出后，确认压缩包存在且非空，并执行完整 7z t 校验。

    仅验证成功后清空 C:\ATF 内的文件和子目录，保留 C:\ATF 目录本身。随后才进入 MMC 阶段。

    BIOS 验证失败 → 不执行最终缓存清理
B

匹配 MMC 打包

从已生成或显式指定的 BIOS 压缩包开始

  1. 05

    从 BIOS 读取 MMC 版本

    读取所有 Trunk_*\dsc\FvRawDefPath.dsc，检查 DEFINE MMC1 和 DEFINE MMC2 指向的 mmc_pkg_<version>_...。

    必须得到唯一、一致的版本；缺失或冲突直接失败。此版本来自构建 / 拼接配置，并非独立解码 ROM 内部版本字段。

    D79 样例：40 处引用均为 0.1022.0
  2. 06

    定位精确匹配的构建

    根据 BIOS 中的版本访问指定 Linux 构建目录：

    MMC_FW.DMR_AP.0.1022.0/
└── DMR_ZCODE_DebugSigned_linux/
    └── *_BuildPkg.7z

    目录中必须恰好有一个 _BuildPkg.7z。不回退到旧包，也不会因为存在 0.1024.0 就改用该版本。

  3. 07

    下载并只提取 binaries

    下载匹配的 BuildPkg，以独立的原生 7-Zip 命令只提取 binaries 子树，保留其中全部文件及许可证。

    • 不提取其他源码、符号和构建目录。
    • 不混入索引目录里的散装 .bin。
    • 拒绝不安全路径和 binaries 内的链接。
    不复用原 BIOS 解压辅助函数
  4. 08

    重打包并逐项验证

    生成 MMCFW_<version>.7z，内部根目录与包名一致：

    MMCFW_0.1022.0\
└── binaries\
    ├── LICENSE-3RD-PARTY.txt
    ├── LICENSE-Intel-Agreement.txt
    ├── mmc_pkg_0.1022.0_...bin
    └── ...

    检查源二进制版本，再完整执行 7z t，确认成品的文件路径、大小、CRC 与源 binaries 一致，且没有其他目录内容。

  5. 09

    发布成品，清理临时文件

    MMC 暂存在输出目录下唯一的 mmc-fw-* 工作目录。新包验证通过后，在同一磁盘卷内原子替换最终同名 MMC 压缩包。

    无论 MMC 成功或失败，只清理本次拥有的暂存目录，不清扫其他任务目录，不修改 BIOS 压缩包。

    最终保留 BIOS + 对应 MMC 两个压缩包

已验证样例 · 2026-11-03

0040.D79.7z → MMC 0.1022.0。实际从 Artifactory 下载并生成新 MMC 包，与 Downloads 参考包逐文件比较；参考包仅用于核对，不是打包来源。

注册不会立即打包，也不会覆盖已存在的同名任务。可使用 -At '15:30' 修改时间，使用 -PythonPath 指定已有依赖的 Python。Python 需为 3.10 或更新版本。

查看调度前提与重试策略

电脑需开机，当前用户需保持登录，并连接 Intel 网络 / VPN。错过时间后会在条件满足时补跑；失败最多重试 3 次，间隔 15 分钟；忽略重叠的计划任务实例；总执行上限 4 小时。BIOS 子进程上限 3 小时，每个 7-Zip 步骤上限 30 分钟。

清理边界与失败分支

错误写日志并返回非零退出码，不静默回退、不把失败当成功

输出目录与 C:\ATF 必须专用

完整流程保留“最新一组”，不是历史归档。不要在这些目录保存其他数据，也不要同时手动运行另一份打包。预检查拒绝危险重叠、根目录、受保护路径及链接 / junction。

BIOS 失败：保留现场

原命令或 BIOS 归档校验失败时，不执行最后的 C:\ATF 清理，便于排查。原脚本在失败之前可能已替换工作空间或清空输出，不能保证旧包仍存在。

MMC 失败：不破坏 BIOS

版本缺失 / 冲突、源包缺失 / 多义、网络或解压 / 校验失败都会报告错误。只清理本次 MMC 暂存，保留 BIOS；新包校验通过前，不替换现存同名 MMC 成品。

缓存清理：只重试可恢复锁定

Windows 文件共享 / 锁定错误 32、33 最多重试 5 次，间隔 2 秒。持续锁定、其他权限问题或清理失败会明确报错，不跳过检查后宣告任务完成。

排查日志：logs\package-bios-YYYYMMDD.log 记录 BIOS / MMC 的选择、执行与结果；logs\restructure-*.log 保存原 BIOS 子进程输出。日志位于项目目录，不随 C:\ATF 或固件输出清理。
